# 001 — Один пакет на сервис

## Контекст

Сервис может иметь несколько протоколов: REST, RabbitMQ, Socket.IO.
Нужно решить как организовать контракты — один пакет на сервис
или отдельный пакет на каждый протокол.

---

## Решение

Один пакет на сервис — все протоколы внутри.

```
@kvint/chat-contracts
  openapi/openapi.yaml
  asyncapi/rabbitmq.yaml
  asyncapi/socket.yaml
```

---

## Почему

- HTTP и события меняются с одинаковой частотой — нет смысла дробить
- Один `package.json`, один SemVer, один changeset на PR
- Обновление зависимостей происходит вручную и осознанно —
  потребитель сам решает когда брать major
- Эксплуатационная простота важнее теоретической чистоты

---

## Альтернатива: пакет на протокол

```
@kvint/chat-contracts-http
@kvint/chat-contracts-queue
@kvint/chat-contracts-socket
```

Оправдано если:

- разные команды владеют разными интерфейсами
- у протоколов принципиально разные release cycles
