# kvint-register-website

Этот скилл регистрирует фронтенд-приложение (вебсайт) в каталоге Kvint: создаёт пакет контрактов и заполняет метаданные. Transport scanning и генерация контрактов не выполняются.

## Язык общения

Веди весь диалог с пользователем **на русском языке**.

## Шаги

### Шаг 1. Сбор данных

Задай пользователю два вопроса (можно сразу оба):

1. **Слаг сайта** — короткое техническое имя (например `admin-panel`). Станет основой пакета контрактов (`packages/admin-panel-module`).
2. **Путь к папке** — папка с клонированным репозиторием фронтенда. Принимается абсолютный путь или просто имя папки (тогда путь строится как `<родительская папка cwd>/<имя папки>`).

### Шаг 2. Валидация пути

- Если передано только имя папки — строй абсолютный путь: `<родительская папка cwd>/<имя папки>`
- Проверь, что папка существует. Если нет — сообщи и остановись.
- Проверь наличие `.git` внутри. Если нет — сообщи и остановись.

### Шаг 3. Скаффолдинг пакета контрактов

Запусти агент `kvint-module-scaffolder`, передав слаг сайта как аргумент.

Жди завершения агента перед переходом к следующему шагу.

### Шаг 4. Подготовка репозитория

Запусти агент `kvint-prepare-project`, передав: `<абсолютный путь> --type=website`

Из вывода агента:
- Извлеки `appPath` — **последняя строка** вывода (перед блоком `MULTIPLE_APPS`, если он есть)
- Проверь, есть ли в выводе блок `MULTIPLE_APPS`

**Если блок `MULTIPLE_APPS` найден:**

Распарси строки блока (формат: `<относительный путь>|<фреймворк>`). Задай пользователю вопрос:

```
Найдено несколько frontend-приложений. Какое из них регистрируем?

1. apps/admin (Next.js)
2. apps/client (Vite/React)
...
```

Дождись ответа пользователя. Возьми выбранный относительный путь и сформируй `appPath = <projectPath>/<выбранный путь>`.

Жди завершения этого шага перед переходом к следующему.

### Шаг 5. Заполнение метаданных

Запусти скилл `kvint-fill-service-yaml` через Skill tool, передав путь к пакету контрактов: `packages/<slug>-module`.

Перед запуском сообщи пользователю:
```
Заполняем метаданные. Тип компонента будет выставлен как "website" — контракты (OpenAPI/AsyncAPI) не нужны.
```

Скилл задаёт вопросы в текущем диалоге — пользователь отвечает напрямую. Жди завершения скилла.

### Шаг 6. Итог

Выведи итоговое сообщение:
```
✅ Вебсайт зарегистрирован

Пакет:   packages/<slug>-module
Сайт:    <appPath>
```

## Правило: не отвечать за вложенные агенты и скиллы

При запуске любого агента или скилла **не перехватывай и не отвечай на их вопросы сам**. Если агент или скилл задаёт вопрос — молчи и жди, пока пользователь ответит напрямую. Единственные решения, которые ты принимаешь: определить `appPath` из вывода агента и выбрать приложение при `MULTIPLE_APPS`.

## Правило: не использовать SendMessage

Инструмент `SendMessage` недоступен в Claude Code. Если агент завершился и требует продолжения — запускай **новый** вызов того же агента с полным контекстом.

## Идемпотентность шагов

Если флоу прервался — при возобновлении проверяй выполненные шаги и пропускай их:

| Шаг | Признак выполнения |
|-----|--------------------|
| 3. Скаффолдинг | `packages/<slug>-module/package.json` существует |
| 5. service.yaml | `packages/<slug>-module/metadata/service.yaml` существует |

Сообщи пользователю, с какого шага продолжаешь.
