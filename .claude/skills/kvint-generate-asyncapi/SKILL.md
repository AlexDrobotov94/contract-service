# kvint-generate-asyncapi

Скилл-диспетчер для генерации AsyncAPI спецификаций из результатов транспортного сканирования. Последовательно запускает специализированных агентов для каждого транспортного протокола.

---

## Триггер

Пользователь просит сгенерировать AsyncAPI для пакета контрактов, имея готовый `transport-scan.*.json`.

Примеры:

- "Сгенерируй asyncapi для chat-contracts"
- "Создай asyncapi контракты из scan-файла"
- "Обнови socket/rabbitmq/websocket спецификации"
- "/kvint-generate-asyncapi"

---

## Входные данные

Нужно выяснить у пользователя (или взять из контекста разговора):

1. `<scan-json-path>` — путь к файлу `transport-scan.*.json`
2. `<package-name>` — имя пакета контрактов (например, `chat-contracts`)

Не начинать запуск агентов до получения явного подтверждения обоих параметров.

### Получение scan-файла: дерево решений

```
Scan-файл явно указан в контексте?
├─ Да → использовать его
└─ Нет → найти файлы в .agent-workspace/transport-scan.*.json
          ├─ Есть файлы → предложить самый свежий (по дате в имени):
          │               "Нашёл scan-файл: .agent-workspace/transport-scan.2026-03-29T12-00-00Z.json
          │                Использовать его для пакета <package-name>?"
          │               Ждать подтверждения пользователя
          └─ Нет файлов → сообщить:
                          "Scan-файл не найден. Нужно сначала просканировать сервис.
                           Укажи путь к директории микросервиса (например, /tmp/chat-service):"
                          → Ждать ответа → запустить kvint-scan-transport <service-dir>
                          → Использовать созданный .agent-workspace/transport-scan.*.json
```

---

## Логика запуска агентов

Запускать агентов **строго последовательно** — каждый следующий стартует только после завершения предыдущего. Параллельный запуск недопустим: агенты читают общие исходные файлы сервиса.

Порядок запуска (чтобы добавить новый агент — достаточно одной строки в эту таблицу):

| # | Агент | Транспорт | Выходной файл |
|---|-------|-----------|---------------|
| 1 | `kvint-socketio-agent` | Socket.IO | `packages/<pkg>/asyncapi/socket.yaml` |
| 2 | `kvint-rabbitmq-agent` | RabbitMQ | `packages/<pkg>/asyncapi/rabbitmq.yaml` |
| 3 | `kvint-websocket-agent` | WebSocket (ws) | `packages/<pkg>/asyncapi/websocket.yaml` |

Для каждого агента аргументы передаются в формате: `<scan-json-path> <package-name>`

Перед запуском первого агента вывести:

```
🚀 Запуск генерации AsyncAPI для пакета <package-name>
   Scan-файл: <scan-json-path>
   Агентов в очереди: 3
```

---

## Обработка результата каждого агента

После завершения каждого агента зафиксировать его результат во внутренней таблице состояния (выводится в финальном отчёте):

| Ситуация | Результат |
|----------|-----------|
| Агент написал файл (Phase 5 Report с путём файла) | `✅ создан: <output-file>` |
| Агент вывел `ℹ️` (транспорт не обнаружен в scan-файле) | `⏭️ пропущен: транспорт не обнаружен` |
| Агент вывел `❌` (ошибка аргументов или сбой) | `❌ ошибка: <сообщение>` |

**Важно:** при `❌` у одного агента — продолжать запуск следующих агентов, не прерывать очередь.

**Интерактивность:** Скилл не принимает решений за агентов и не отвечает на их вопросы. Если агент задаёт вопрос пользователю — пользователь отвечает напрямую. В стандартном потоке агенты не задают вопросов — они читают только scan-файл.

---

## Финальный отчёт

После завершения всех агентов вывести сводку:

```
📋 AsyncAPI генерация завершена — <package-name>

| Транспорт      | Статус    | Файл                                       |
|----------------|-----------|--------------------------------------------|
| Socket.IO      | ✅         | packages/<pkg>/asyncapi/socket.yaml        |
| RabbitMQ       | ⏭️ skip   | (транспорт не обнаружен в scan-файле)      |
| WebSocket (ws) | ✅         | packages/<pkg>/asyncapi/websocket.yaml     |

Создано файлов: 2 из 3
```

Если хотя бы один агент завершился с `❌`:

```
⚠️ Ошибки:
  - kvint-rabbitmq-agent: <сообщение ошибки>
```

Если все агенты вернули `⏭️` (ни один транспорт не обнаружен):

```
ℹ️ В scan-файле не обнаружено транспортов для AsyncAPI.
   asyncapi/ директория не создана.
   Проверь, что сервис содержит Socket.IO, RabbitMQ или WebSocket.
```

Если хотя бы один файл создан — добавить напоминание:

```
💡 Не забудь добавить записи protocol в service.yaml для созданных файлов,
   если их там ещё нет.
```
