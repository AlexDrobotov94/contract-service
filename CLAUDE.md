# contract-service

Service discovery and contract management portal for microservices. Scans monorepo packages and displays their API contracts (OpenAPI, AsyncAPI, etc.).

## Project Structure

```
apps/contracts-ui/    # Next.js 16 app (main UI)
packages/             # Contract packages (e.g. chat-contracts)
tooling/              # JSON schemas + type generation
```

### contracts-ui follows Feature-Sliced Design (FSD):

```
src/
  app/        # Next.js App Router, layouts
  pages/      # Page-level components
  widgets/    # Composite UI (e.g. services-table)
  entities/   # Domain models (service)
  shared/     # Utils, configs, UI atoms
```

## Common Commands

```bash
# Dev
npm run dev              # Start all apps (Turborepo)
cd apps/contracts-ui && npm run dev  # Start UI only

# Build & Check
npm run build
npm run check-types
npm run lint

# Type generation (from JSON schema)
npm run generate:types   # tooling/schemas/service.schema.json → shared/types/service.generated.ts
```

## Key Conventions

### Adding a new contract package

1. Create `packages/<name>/` with `package.json` containing `"contracts": true`
2. Add `metadata/service.yaml` following the Kvint v1 schema
3. Run `npm run generate:types` if the schema changed

### Service metadata format (`metadata/service.yaml`)

```yaml
apiVersion: kvint/v1
kind: component
namespace: default
id: <service-id> # must be registered in tooling/schemas/services.schema.json
name: Human Readable Name
owner: group:default/<team>
lifecycle: experimental | production | deprecated
system: <system>
domain: <domain>
source: https://gitlab.kvint.io/<group>/<repo>  # optional, shown as VIEW SOURCE in About block
links:                                            # optional arbitrary links
  - url: https://grafana.kvint.io/d/<id>
    title: Grafana
    icon: alert  # alert | support | website
contracts:                                        # optional — omit for type: website / library
  - protocol: http
    path: openapi/openapi.yaml
  - protocol: socket
    path: asyncapi/socket.yaml
  - protocol: websocket
    path: asyncapi/websocket.yaml
  - protocol: rabbitmq
    path: asyncapi/rabbitmq.yaml
```

Supported protocol values: `http`, `rabbitmq`, `socket`, `websocket`, `grpc`, `graphql`.
Each asyncapi transport is a separate entry — one file per transport, no merging.

For `type: website` and `type: library`, `contracts` is optional — the component is registered in the catalog without contract files.

### Contract package folder structure

```
packages/<name>-contracts/
├── package.json            # "contracts": true required
├── metadata/
│   └── service.yaml
├── openapi/
│   └── openapi.yaml        # OpenAPI 3.1, generated by kvint-openapi-*-agent
└── asyncapi/
    ├── rabbitmq.yaml       # AsyncAPI 3.1.x: RabbitMQ channels + operations
    ├── socket.yaml         # AsyncAPI 3.1.x: Socket.IO channels + operations
    └── websocket.yaml      # AsyncAPI 3.1.x: native WebSocket (ws library) channels + operations
```

Each asyncapi file is a complete, self-contained contract for its transport. They are referenced directly in `service.yaml` — no merge step required.

### Service discovery

- `getServices()` in `entities/service/api/get-services.ts` is **server-only**
- Scans all packages with `"contracts": true` in `package.json`
- Reads `metadata/service.yaml` from each package dir

### Schemas

- Single source of truth: `tooling/schemas/service.schema.json`
- Service IDs must be registered in `tooling/schemas/services.schema.json`
- TypeScript types are auto-generated — do not edit `shared/types/service.generated.ts` manually
